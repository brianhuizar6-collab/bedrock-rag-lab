# Data Dictionary — Usage Metering & Billing Pipeline

**Document owner:** Data Engineering, Billing Platform
**Classification:** Internal
**Version:** 1.0
**Last updated:** 2026-09-10

This document defines every table, column, data type, and business meaning used by the
Usage Metering & Billing pipeline. It is one of the four authoritative source documents
for this knowledge base (alongside the schema, the pipeline README, and the data quality
rules).

---

## Table: `customers`

One row per billing account.

| Column | Type | Nullable | Description |
|---|---|---|---|
| `customer_id` | VARCHAR(32) | No | Primary key. Unique identifier for the billing account. |
| `account_name` | VARCHAR(120) | No | Display name of the account. |
| `plan_code` | VARCHAR(20) | No | The account's current plan. Must be one of: `STARTER`, `GROWTH`, `SCALE`, `ENTERPRISE`. |
| `signup_date` | DATE | No | Date the account was created. |
| `billing_country` | CHAR(2) | No | ISO 3166-1 alpha-2 country code used for tax/currency rules. |
| `status` | VARCHAR(20) | No | One of: `TRIAL`, `ACTIVE`, `PAST_DUE`, `CANCELED`. |

**Primary key:** `customer_id`

---

## Table: `subscriptions`

A subscription is a specific billing agreement under a customer — most customers have
one, but a customer can run multiple subscriptions (e.g., separate production and
staging environments billed independently).

| Column | Type | Nullable | Description |
|---|---|---|---|
| `subscription_id` | VARCHAR(32) | No | Primary key. |
| `customer_id` | VARCHAR(32) | No | Foreign key to `customers.customer_id`. |
| `plan_code` | VARCHAR(20) | No | Plan this subscription is billed under. Same allowed values as `customers.plan_code`. |
| `billing_cycle` | VARCHAR(10) | No | One of: `MONTHLY`, `ANNUAL`. |
| `start_date` | DATE | No | Date the subscription became active. |
| `end_date` | DATE | Yes | Date the subscription ended. Null means the subscription is still active. |
| `status` | VARCHAR(20) | No | One of: `ACTIVE`, `PAUSED`, `CANCELED`. |

**Primary key:** `subscription_id`
**Foreign key:** `customer_id` references `customers.customer_id`

---

## Table: `usage_events`

Raw metered usage, reported by source systems throughout each hour. This is the highest
-volume table in the pipeline.

| Column | Type | Nullable | Description |
|---|---|---|---|
| `event_id` | VARCHAR(32) | No | Primary key. Assigned by the reporting source system. |
| `subscription_id` | VARCHAR(32) | No | Foreign key to `subscriptions.subscription_id`. The subscription this usage is billed against. |
| `event_ts` | TIMESTAMP | No | UTC timestamp the usage occurred. |
| `metric_type` | VARCHAR(20) | No | What was consumed. Must be one of: `API_CALLS`, `STORAGE_GB`, `SEATS`, `COMPUTE_MINUTES`. |
| `quantity` | DECIMAL(14,4) | No | Amount of the metric consumed in this event. Must be greater than 0. |
| `unit_cost` | DECIMAL(10,6) | No | Price per unit of `quantity`, in the account's billing currency, at the time of the event. |
| `source_system` | VARCHAR(30) | No | Which system reported the event: `API_GATEWAY`, `STORAGE_SERVICE`, `SEAT_MANAGER`, or `COMPUTE_SCHEDULER`. |

**Primary key:** `event_id`
**Foreign key:** `subscription_id` references `subscriptions.subscription_id`
**Business rule:** an event whose `subscription_id` does not correspond to a subscription
that was `ACTIVE` at `event_ts` is not billable — see the data quality rules document for
how these are handled.

---

## Table: `invoices`

Output table produced by the monthly billing run. One row per subscription per billing
period.

| Column | Type | Nullable | Description |
|---|---|---|---|
| `invoice_id` | VARCHAR(32) | No | Primary key. |
| `subscription_id` | VARCHAR(32) | No | Foreign key to `subscriptions.subscription_id`. |
| `billing_period_start` | DATE | No | First day of the billing period covered. |
| `billing_period_end` | DATE | No | Last day of the billing period covered. |
| `amount_due` | DECIMAL(12,2) | No | Total amount billed for the period, computed from `usage_events`. |
| `status` | VARCHAR(20) | No | One of: `DRAFT`, `ISSUED`, `PAID`, `OVERDUE`, `VOID`. |
| `generated_ts` | TIMESTAMP | No | When the invoice was generated by the billing run. |
| `paid_ts` | TIMESTAMP | Yes | When payment was received. Null until paid. |

**Primary key:** `invoice_id`
**Foreign key:** `subscription_id` references `subscriptions.subscription_id`

## Glossary of domain terms used in this dictionary

- **Metering**: the process of recording how much of a billable resource (API calls,
  storage, seats, compute minutes) an account consumed.
- **Rating**: converting metered usage into a monetary amount, by applying `unit_cost`.
- **Proration**: adjusting a billed amount when a subscription is only active for part of
  a billing period, so the customer is charged for the fraction of the period they
  actually used.
- **Billing period**: the date range (`billing_period_start` to `billing_period_end`) an
  invoice covers — normally one calendar month.
